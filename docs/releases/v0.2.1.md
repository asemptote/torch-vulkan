# torch-vulkan 0.2.1

A patch release of 0.2.0 with one correctness fix. Upgrading is recommended.

## Fixed

- **`clamp` of integer tensors with only one bound.** `torch.clamp`,
  `clamp_min` and `clamp_max` (and their in-place and `out=` forms) of int32,
  int16, int8 and uint8 tensors with a scalar lower or upper bound, but not
  both, gave wrong results: the missing bound was read as 0 or -1. For
  example, `torch.clamp(x, min=10)` of an int32 tensor returned -1 for every
  element, `clamp_max` of int32, int16 or int8 also raised negative elements
  to 0, and `clamp_min` of uint8 returned 255. With both bounds given, with
  tensor bounds, and for int64 and floating-point tensors the results were
  already correct.

  You are affected if you clamp integer tensors of those dtypes on `"vk"`
  with one scalar bound. Nothing else changes from 0.2.0.

## Installing

Wheels for Windows and Linux (x86_64), Python 3.10 or newer, PyTorch 2.14:

    pip install "torch==2.14.*"
    pip install <wheel URL from the assets below>

On Android (Termux), build from source with the prebuilt kernels: extract
`torch-vulkan-spirv-v0.2.1.tar.gz` and run `tools/build-termux.sh` with that
directory.
